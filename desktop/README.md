# Windows disposable TEST application

This adapter packages the existing protected HTTPS custom server and approved frontend. Production remains disabled. It uses pinned Electron45.3.3, separate verified Node24.22.3, and the existing better-sqlite3 Windows x64 prebuild. No Node installation, editor, development server or internet is needed on the target PC.

`main.cjs` owns sandboxed in-memory Admin/Salesperson windows. Each role still authenticates through its fixed HTTPS origin. Setup and native owner recovery have fixed-purpose sender/frame/file-URL validated preloads. Role windows have only a narrow typed operation-marker bridge: exact role/frame/HTTPS origin validation plus genuine existing gateway authentication on every access. No role renderer receives Node, filesystem, SQL, keys or a shell bridge. Certificate verification is restricted to the exact provisioned loopback certificate; no Windows trust-store or security-policy changes.

`web/src/server/desktop/test-entry.ts` creates a fresh disposable protected TEST identity through the existing sole account provisioner. Existing data is never auto-migrated, reset or repaired. Interrupted setup is retained and fails closed. The native installer mutex coordinates code installation; existing native runtime ownership remains the business-writer authority.

Existing TEST.17 retains its protected default data root, `%LOCALAPPDATA%\ShopPOSTestData`. TEST.18 remains harness-only: launch requires `--disposable-harness` and an absolute `SHOP_POS_DESKTOP_TEST_DATA` path whose leaf is `posdt-<UUID>`. TEST.19 is a separate normal-launch TEST release. Its direct no-argument launch is accepted only from the exact versioned install directory, with the expected Electron version/profile identity and no harness data override. It uses the protected, persistent data root `%LOCALAPPDATA%\Programs\SalamTech\ShopPOSTestData\0.2.0-test.19\ShopPOSTestData`, separate from TEST.17/18. TEST.19 installs under `%LOCALAPPDATA%\Programs\SalamTech\ShopPOSTest\0.2.0-test.19`, has a unique AppId/uninstall identity, and creates one version-named per-user Desktop shortcut. Uninstall retains its TEST data and backups.

`build-test.ps1` requires a previously verified isolated Next build, the verified Electron extraction, patched Node, official pinned Node license and reviewed workspace Inno compiler. The normal-launch installer is reserved for TEST.19 and refuses a reused AppId registration, install directory, or Desktop shortcut. It creates a new output, copies the exact locked production dependency graph from a scripts-disabled source install; optional development peers are excluded without dropping required providers, retains notices, burns reviewed fuses, hashes the actual payload and compiles an unsigned per-user offline installer. Failed outputs remain retained; there is no force-overwrite, automatic migration, or application launch during installation.

The manifest checks byte consistency, missing/unlisted code, redirects, hard links, version/schema flags and path bounds. These unsigned TEST artifacts do not provide a signed trust chain against an attacker who can replace both application code and its manifest. Real signing/custody and production release remain separate owner decisions.
